# Course submission checklist

Repository materials are prepared from available implementation evidence. This does not certify that every academic deliverable or live-host check is complete.

- [x] Project source, meaningful recovered snapshot commits and original Git history retained.
- [x] README with description, features, stack, setup, database steps, live URL and developer.
- [x] Four synthetic screenshots published with explicit owner approval.
- [x] `.gitignore`, example configuration, clean installation SQL and additive migrations.
- [x] Architecture, use-case, flowchart and ERD sources; full database dictionary.
- [x] Current proposal reconstruction and six-chapter technical documentation.
- [x] Recorded test results and a manual deployment/accessibility checklist.
- [ ] Student verifies academic identity fields, instructor-approved title/scope and school formatting.
- [ ] Student verifies live deployment against this repository version, using their private hosting credentials.
- [ ] Student executes and records the required exact viewports: 1366x768, 768x1024, 375x667.
- [ ] Student completes keyboard, screen-reader, direct-receipt access and live network-failure checks.
- [ ] Student prepares and rehearses the presentation and records the 5-10 minute demonstration video.
- [ ] Student assembles the final folder with source, clean database SQL, documentation PDF, diagrams, presentation PDF and README.txt using their actual student ID.

No administrator account exists in this implementation. Do not invent one to fill a template. If the instructor needs a demo account, create a dedicated test account and share its credentials privately through the permitted submission channel, not this public repository.

The assignment has inconsistent modern-feature counts (three in its detailed section; two later). Demonstrate at least three implemented features. AI assistance does not replace the student's understanding or permit live AI answers during defense.
